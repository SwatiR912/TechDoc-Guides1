# Documentation playbook

Methods for the parts of documentation work that are not writing: reviewing a draft, planning a documentation project, and auditing a set that already exists.

Each guide is written to be handed to someone else and followed — a working procedure rather than a theory of documentation.

## The guides

| Guide | Use it when |
| --- | --- |
| [Running a documentation review](guides/running-a-documentation-review.md) | A draft needs feedback that improves it without demoralising the author. |
| [Planning a documentation project](guides/planning-a-documentation-project.md) | A product is shipping and nobody has decided what documentation it needs. |
| [Auditing an existing documentation set](guides/auditing-an-existing-doc-set.md) | Documentation has been inherited and its problems are not yet known. |

## Why these three

Writing is the visible part of the job and the smallest share of the hours. What decides whether documentation is any good happens before the writing, when scope is set, and after it, when someone reviews it honestly or audits what has drifted.

All three guides share one bias: **make the judgement explicit**. A review that says "looks good" teaches nobody. An audit that reports 300 findings without ranking them will be ignored. A plan that lists every document a product could have is not a plan.
